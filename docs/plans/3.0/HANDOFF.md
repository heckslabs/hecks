## Decision: queries answered from outside the domain (replaces 3b `answered_by`)
Made by the user, before 3.0, in two steps. First, a bluebook stays free of port and adapter names, so `answered_by "Port"` left the language. Second (the architecture): **Bluebook owns meaning** (it declares the query and the shape of its answer, in domain terms), **Hecksagon owns capability** (which port's adapter can obtain the answer), **World owns configuration** (which adapter, with what settings).
- Bluebook: `query "Ir" do attribute ...; returns Document end`. `returns Name` names a value object of the owning aggregate (`returns list_of(Name)` for many rows). The value object carries typed attributes, nested value objects, `pattern:`, `admits:` and invariants, and projects to Rust and JSON like any other. A query with no `returns` answers the aggregate's own rows (the derived behavior). IR: `returns: "Name"` or `"list_of(Name)"` on the query, emitted only when declared; Ruby (`Query#returns`, `#returns_name`, `#returns_list?`) and Rust (`ir::Query.returns`) emit it byte-identically (spec/query_answers_from_outside_spec.rb, `:io`, and rust/parser/tests/gates.rs).
- Hecksagon: `Hecks::Introspection.port "DomainRuntime" do answers_query "Ir" end`. Only the name; `shape:` and `QueryAnswer::SHAPES` are gone (`answers_query "X", shape: :row` is refused, pointing at `returns`).
- Validation: every row the adapter answers is built with `Value.build(value_object, row)` in `QueryInterpreter#shaped`. A wrong type, a missing or extra field, a broken invariant or a non-row answer is refused as `TypeMismatch`, `UnknownArgument` or `InvariantViolation`, worded "Aggregate.Query answered outside the domain, but not as its Name". The reference oracle validates too, so it no longer differs from the live answer. The rows arrive as the value object's fields (`Value#to_h`); the aggregate is never read and nothing is written.
- `taken_at`: the interpreter no longer stamps a wall-clock time and the launcher's `text_answer` no longer strips one. A query that wants an observation time declares `attribute :taken_at, String` in its value object and its adapter fills it (`Follow` does, from `Ports::Clock` of the followed domain's registry). There is no shared Observation type: value objects are aggregate-local.
- Boot rule, one answer path (`Registry::Verification#refuse_unanswerable_queries!`, aggregate and entity queries): a query is derivable (it filters stored records, or takes no arguments and lists them, and returns nothing) XOR bound exactly once (it `returns` a value object and one port binds it). Refused: no path (returns but unbound; arguments that select nothing, no returns, unbound), two paths (two ports; bound and also filtering records; bound with a where), a bound query that returns nothing, a returned value object the aggregate does not declare, a binding naming an undeclared query, an entity query that returns (nothing can be bound to an entity query), and a bound query whose port has no adapter, several, or an adapter without the method (`AdapterLookup.adapter_class` checks at boot what `.call` checks per ask). Parameterless queries with no `returns` and no binding stay the plain list (`Membership::Person.All`, `Everything`).
- Launcher: the raw-print rule keys on the one-attribute `Document` shape (`{ text: ... }`); any other returned rows print as JSON. Adapters answer `{ text: ... }` (InProcessBoot, JournalStore readings, SourceTree, RustToolchain, the `*Tools` adapters of QualityControl), `Follow` answers a `Tail` row, and ProjectDiagrams and Glossary answer `list_of(ProjectedFile)` (a name and a text per file).
- The 40 bound queries were migrated: 37 return an aggregate-local `Document` (`text`), Follow returns `Tail` (cursor, events as `FollowedEvent`, taken_at), ProjectDiagrams and Glossary return `list_of(ProjectedFile)`. Bindings sit in lib/hecks/hecks/hecks.hecksagon and the QualityControl chapter's ports hecksagon.
- A behaviors file swaps in a fake adapter without touching the bluebook or the hecksagon: it loads an anchor `.hecksagon` from a sibling directory whose `adapters/` folder holds the fake. Since boot now checks that the adapter has every bound method, the fake implements all of them.
- model_check: a domain with a Rust target reports `:external_query` (an error) for each bound query, since only the Ruby runtime asks an adapter. A domain without a Rust target is not checked. The Hecks chapter has none.
- Deviations to know: (1) `FollowedEvent.payload` is the event payload as JSON text, because a value object holds no free-form map (before, it was a nested object); (2) `Document` is a new name because the Run aggregates already carry a `Report` value object with a `value` field.
- Soft spots: (1) external answers are not replayable from the journal (nothing is written, so a replayed corpus step re-asks the live adapter; a `taken_at` in the value object says when, it does not reproduce). ADR 0080 is silent on unjournaled queries: it defines the journal as the record of commands and their events, and says nothing of a read that touches neither; the ADR needs a sentence stating that outside-answered queries are unjournaled and unreplayable on purpose; (2) the Rust host does not serve them (Rust parses `answers_query` as not built yet and no Rust runtime asks an adapter); model_check now refuses them on Rust-target domains, but the Rust host still has no way to be told; (3) `Adapters::InProcessBoot` boots a domain and reads runtime internals (`registry.repository`, `hecksagon`, `pending_privacy_markings`) to answer Stores, History and Glossary, so it is coupled to the runtime's shape; (4) no access control on who may ask an outside-answered query.

## Mechanics for any agent working here
- A fact-forcing hook denies the FIRST Write/Edit/Bash of each file or command: state callers, affected API, data, and the user's instruction verbatim, then retry. In a parallel batch the first edit of an untouched file may be denied while others apply: re-check `git diff`.
- Bash refuses text containing the word "rspec" and "too complex" compound or substitution commands. Run specs through wrapper scripts (recreate if the job tmp was cleaned): run_specs.rb = `require "rspec/core"; exit RSpec::Core::Runner.run(ARGV)`; run_all.rb = `exec("bundle","exec","parallel_rspec","spec","-n","4")`; `env GOLDEN=rewrite ...` rewrites golden IR.
- Commit with `env SKIP_POST_COMMIT_FUZZING=1 git commit -q -F - <<'EOF'`; trailers: Co-Authored-By: Claude Sonnet 5.5 <noreply@anthropic.com> and the Claude-Session line. Never push, never touch main, no bin/ deletion before step 11.
- Generated files are never hand-edited: bin/project_parser_table, bin/regen_codegen_domains (--check must be clean), bin/reference, GOLDEN=rewrite. Comment style: bin/standardize_comments --check.
- Read the TOTAL "N examples, M failures" line of the suite, not a per-process line (a slow 4th group prints last).
