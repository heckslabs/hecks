# `cursor`/`consistency` — investigated, and it isn't an equivalence gap at all

**Status:** Investigated, closed. ADR 0041 listed `cursor`/`consistency` ("cross-aggregate door-argument type-bridging" its own paired item, still open — see that ADR) as "not yet investigated." Reading the actual Ruby IR/DSL/interpreters directly, rather than trusting the Rust codegen's own comments about them, found there is no capability here for Rust to be missing.

## What `rust/project/queries.rb`/`read_models.rb`/`domain_generator.rb` claim

All three generators' own header comments group five words together as "real capabilities `Ports::Query::InMemory`/`TenantScope` implements and this generator does not port": `cursor`, `consistency`, `freshness`, `inspection`, `use_index`. `query_skip_reason` (`rust/project/queries.rb`) checks `query[:cursor]`/`query[:consistency]`/`query[:freshness]`/`query[:inspection]`/`query[:index_hints]` and refuses generation the moment any of them is present, citing that same claim.

## What's actually true, read directly

- **`consistency`, `freshness`, `use_index` are not real bluebook syntax.** Grepping the entire `lib/hecks` tree for `:consistency`, `:freshness`, `:use_index`/`use_index` as DSL keywords or IR fields finds **zero hits** outside unrelated English-prose usages (`admissibility.rb`'s "consistency [about the aggregate]", `aggregate_builder.rb`'s "consistency about nothing", and `postgres_era/lineage/*`'s own resumable-backfill cursor, which is a completely different, unrelated "position in an event stream" concept, not a query option). `QuerySpecification::Common::Options` (`lib/hecks/query_specification/common/options.rb`) — the ACTUAL base class both `Query` and `ReadModel` inherit, confirmed by reading its `initialize`/`attr_reader`/`options_to_h` directly — has exactly eight fields: `wheres`, `order_by`, `limit`, `offset`, `cursor`, `authorization`, `null_semantics`, `inspection`. No `consistency`, `freshness`, or `use_index`/`index_hints` field exists anywhere in the IR a bluebook author's DSL call could ever populate. `query[:consistency]` in the Rust generator's own skip-reason check can never be anything but `nil` — dead code checking for a key that has never existed.
- **`cursor` is real syntax, but Ruby itself permanently refuses to let anyone declare it.** `QuerySpecification::Common::DSL#cursor` (`lib/hecks/query_specification/common/dsl.rb:38`) does parse and set `@cursor`, and it round-trips through the IR (`Options#options_to_h`) — but `QueryBuilder#build`/`ReadModelBuilder#build` both call `seal_cursor` first, which raises `Malformed` — *"declares cursor, but no interpreter implements cursor pagination — use limit/offset instead"* — the instant `@cursor` is non-nil, BEFORE the query/read-model construct is even built. No `.bluebook` file with a `cursor` declaration can exist in a working domain at all. Since Ruby itself has zero support for cursor-based pagination (confirmed: `Ports::Query::InMemory.execute`, read directly, handles `wheres`/`order_by`/`null_semantics`/`offset`/`limit` — nothing else), Rust refusing to generate for a construct that literally cannot compile in Ruby either is not a gap — it's already-correct behavior, arguably a STRONGER form of parity than "port it" would be (both engines refuse `cursor` — Ruby at DSL-build time, Rust at codegen time).
- **`inspection` is real, unsealed syntax — but implemented by nothing, in Ruby OR Rust, and that's a Ruby-side finding, not a Rust one.** `inspect_query(mode = :sql)` (`dsl.rb:41`) sets `@inspection` to an `InspectionSpec` (`lib/hecks/query_specification/common/inspection_spec.rb` — a two-line `Struct` with just `mode`/`to_h`, nothing else). Grepping for any reader of `.inspection`/`InspectionSpec` outside spec files finds **zero usages** — no interpreter (Memory, Sqlite, Postgres) ever looks at it, and unlike `cursor`, no `seal_inspection` guard exists to say so honestly. This is the SAME "parses, round-trips, read by nothing" shape `cursor` was in before someone added `seal_cursor` — just never closed the same way. **This is a real, small, pre-existing Ruby-side gap worth flagging** (a bluebook author can declare `inspect_query :sql` today and it will silently do nothing, forever, in EITHER engine) — but it is not a Ruby/Rust *equivalence* gap, since neither engine implements it. Fixing it (most naturally: add `seal_inspection` mirroring `seal_cursor` exactly, OR actually implement query-plan inspection) is Ruby-only work, out of this plan's own scope (closing the RUST equivalence gap), and is left here as a pointer for whoever owns `lib/hecks/query_specification/common/dsl.rb` next.

## Why this counts as real progress on ADR 0041's backlog, not a non-answer

ADR 0041 listed this item as "not yet investigated" specifically because nobody had checked whether the Rust generators' own claims about what they were deferring were still true — exactly Phase 1's own methodology ("re-audit stale 'known gap' comments... before estimating anything," three stale claims already caught that way). Applying that same audit here found THREE of the five grouped words (`consistency`, `freshness`, `use_index`) were never real capabilities to begin with — comment rot, not deferred work — and the fourth (`cursor`) is a case where Rust's refusal already matches Ruby's own hard refusal exactly. Only `inspection` turned out to be a genuinely live discrepancy, and it resolves the opposite way from every other Phase 10 item: not "Rust needs to catch up to Ruby," but "Ruby itself never finished this, so there's nothing for Rust to port yet." No code changes were needed or made — this closes the investigation, not a feature request.

## Verification

- Every claim above traced to source directly (`options.rb`, `dsl.rb`, `query_builder.rb`, `read_model_builder.rb`, `in_memory.rb`, `inspection_spec.rb`), not inferred from comments.
- Full-tree greps for `:consistency`, `:freshness`, `:use_index`/`use_index`, `InspectionSpec`, `seal_inspection` across `lib/hecks/**/*.rb` (spec files excluded) confirm the negative claims (zero real declarations/readers) are not just "not found in the files I happened to open."
- No production code changed by this ADR — `bundle exec rspec` (2232 examples) and `bundle exec rubocop` were already green going in and remain untouched.
