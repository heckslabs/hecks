release — Certify, publish and pin versions.

  hecks <Aggregate.command>! [name=value …]    do something
  hecks <Aggregate.query> [name=value …]       read something

commands:
  PublishingRun:
    One release of the gem, or the rehearsal of it: judged by the facts, then carried out.
    publish!      Tag the merged release commit, publish the gem, and get the client package published
    publish_gem!  Build the gem and push it to the gem registry, with the key the vault holds
  PromotionRun:
    One move of a lane onto a commit, or the rehearsal of it: judged by the facts, then carried out.
    watch!        Fault when a lane has stood behind the lane it follows for longer than its Lane row allows
    promote!      Move a lane onto a commit that has passed every required check, or with no --confirm rehearse the move
  Registry:
    A bluebook registry repository: packages versioned in it and released as tags.
    release!      Tag a package of this registry at the version its bluebook.yml carries (also: package.release!)
  Package:
    One package of the bluebook registry, vendored into a project and pinned.
    vendor!       Pin a package of the bluebook registry into this project, at a release or a commit
    revendor!     Pin a package that was vendored before again, for the newest release or the same one

queries (nothing here changes anything):
  Release:
    One gem version: the record of what is running and what was shipped.
    shipped  Every version that was tagged, published and verified.
  Registry:
    A bluebook registry repository: packages versioned in it and released as tags.
    check    Judge every package against its latest release: a changed package needs a newer version and a changelog entry. (also: package.check)
    digest   Print a package's content digest and shape labels, as its bluebook.lock records them. (also: package.digest)
  Package:
    One package of the bluebook registry, vendored into a project and pinned.
    verify   Check every vendored package against its bluebook.lock, then describe them as the manifest a client image carries.
